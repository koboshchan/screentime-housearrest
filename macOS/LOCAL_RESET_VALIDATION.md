The SIP-off local reset is selected only by a fresh csrutil status result explicitly reporting disabled. SIP enabled and unknown retain the original local usage writer with logout guidance. Selection is not tied to a macOS version.

Before any store write or process termination, apply creates and independently verifies the existing current-source usage snapshot and a second sealed reset snapshot. The reset snapshot contains all discovered backlight segments, every DeviceActivity cache file, directory structure, modes, owners, and explicit absent-cache state. Copies are streamed in bounded chunks; file hashes, exact inventory, private modes, completion digest, and current source state are checked again. Override backs up the current source, not the stale requested revision.

Backlight discovery enumerates the real system stream directory. It selects the latest header-created segment for new events, removes day events across all segments, and has no fixed numeric filename. The cache root comes from the current user's Darwin directory, not a fixed hash or username. Cache removal walks only backed-up entries, refusing symlinks, nonregular files, and newly introduced entries. The original backlight protobuf and knowledgeC display rows are retained.

There is no installed native privileged helper in this project. This implementation does not request or store passwords, run sudo, change permissions on source stores, grant Full Disk Access, or disable SIP. SIP disabled alone does not grant system-backlight access. A read/backup denial aborts before mutation; a write-capability denial after backup explicitly reports the retained backup paths. There is no downgrade to a reported logout-only success on the selected reset path.

Reset process commands target the current UID only. pkill no-match is accepted only without error output; actual denial fails. launchctl kickstart uses the current UID, not the original hardcoded UID. Restart failure and any write/cache failure report possible partial changes with both backup paths. The writes are not atomic across stores and processes, and no automatic rollback is claimed. Actual native Screen Time UI refresh and cross-device aggregation are not verified.

Swift compilation and all 16 Swift tests pass. Python compilation, diff checks, and publishable-source audit pass with zero findings.
